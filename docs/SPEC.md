## 2. 기술 구성

| 영역 | 선택 | 상태 |
|---|---|---|
| 화면 | Vue 3 + Vite | [확인] Vue / [가정] Vite |
| 코드 작성 방식 | Options API (회사와 같은 방식이라 읽기 편함) | [가정] |
| 데이터·로그인·파일 | Supabase 무료 요금제 (PostgreSQL) | [확인] |
| 로그인 방식 | 구글 / 카카오 소셜 로그인 둘 다 제공 (Supabase 기본 지원, 0원) | [확인] |
| 계정 묶기 | 하지 않는다. 구글 계정과 카카오 계정은 각각 별개의 가계부 | [확인] |
| 카카오 이메일 | Supabase가 카카오에 이메일 권한을 자동 요청 → 개인 개발자 비즈 앱 전환(사업자 불필요) 또는 Supabase에서 '이메일 없는 사용자 허용' 설정 | [미확인] |
| 계정 나뉨 대책 | 로그인 화면에 "지난번에 카카오로 로그인했어요" 표시(이 기기 기준), 설정 화면에 현재 로그인 계정(구글/카카오, 이메일 또는 닉네임) 표시 | [가정] |
| 화면 올리는 곳(호스팅) | 무료 정적 호스팅 (예: Vercel, Netlify, Cloudflare Pages 중 하나) | [미확인] 0원 조건 확인 후 결정 |
| 홈 화면 추가 | 폰 홈 화면에 앱처럼 추가(PWA) | [가정] ④ 단계 알림과 연결 |
| 금액 저장 | 원 단위 정수 (소수점 없음) | [가정] |

**보안 원칙** [가정]
- 모든 테이블에 `user_id`를 두고, 로그인한 본인 데이터만 읽고 쓸 수 있게 막는다 (Supabase 행 단위 보안).
- 카드번호·계좌번호는 저장하지 않는다. 결제수단은 사용자가 정한 이름(별칭)과 종류만 저장한다.
- 이미지에서 카드번호·카드사는 읽지 않는다. 이미지 원본은 읽고 나면 지운다(③ 단계).

## 5. 화면별 동작 규칙

### 5-1. 입력·수정 화면 (①)
- [확인] 기록 종류는 지출·수입 두 가지. 화면 위쪽 버튼으로 바꾼다.
- [가정] 날짜 기본값은 오늘, 캘린더에서 날짜를 눌러 들어오면 그 날짜.
- [확인] 분류는 버튼으로 보여주고 탭 한 번으로 고른다. 안 고르면 '미분류'로 저장.
- [확인] 결제수단은 등록한 목록에서 고른다. 목록 맨 끝에 '새로 등록'.
- [가정] 결제수단 기본값은 마지막으로 쓴 수단. 몰라도 '미지정'으로 저장 가능.
- [보류] 결제수단 기본값의 세부 규칙(가게별 / 전체) → 써보면서 결정.
- [가정] 전에 입력한 가게 이름이면 그 가게의 마지막 분류·결제수단을 미리 골라둔다 (①에서는 가게 이름이 똑같을 때만).
- [확인] 등록된 모든 기록은 수정·삭제할 수 있다.

### 5-2. 캘린더 (①)
- [확인] 날짜 칸에 가게 이름과 금액을 보여준다 (예: 다이소 12,300원). 여러 건이면 [가정] 대표 1건 + '외 N건' 또는 그날 합계.
- [확인] (②) 오늘 이후 고정 항목은 '예정'으로 흐리게, 날짜가 지나면 실제 기록으로 바뀐다.
- [가정] (②) '금액 입력 필요' 고정 지출은 눈에 띄게 표시한다.

### 5-3. 통계 (①, ② 확장)
- [확인] 항상 '이번 달(1일~오늘)'로 열린다. 지난번 선택을 기억하지 않는다.
- [확인] 분류별·가게별 합계를 둘 다 보여준다.
- [확인] (②) '저축/투자' 분류는 소비 합계와 따로 보여준다. 예: "이번 달 쓴 돈 70만 원 · 저축/투자 50만 원"
- [확인] (②) 실제 기록만 넣는다. 예정인 고정 항목, '금액 입력 필요' 상태는 넣지 않는다.
- [가정] (②) 기간 빠른 선택: 이번 달 / 지난달 / 최근 30일 / 직접 선택.

### 5-4. 고정 항목 (②)
- [확인] 고정 수입(월급 등)과 고정 지출(보험료 등)을 등록한다.
- [가정] 1차는 매달 반복만 지원 (매년·매주는 v2).
- [확인] 항목마다 날짜가 주말이면 '앞 평일' / '뒤 평일' 중 고른다 (예: 월급 → 앞 금요일, 보험료 → 뒤 월요일).
- [가정] 그 달에 없는 날짜(예: 31일)는 그 달 마지막 날로 본다. 주말 규칙은 그 뒤에 적용한다.
- [가정] 1차는 주말만 피한다. 공휴일까지 피할지는 [미확인].
- [가정] 등록할 때 '금액 고정 / 매달 다름'을 고른다.
  - 금액 고정 → 날짜가 되면 자동 기록
  - 매달 다름 → 날짜가 되면 '금액 입력 필요' 상태로 만들고 사용자가 채운다
- [확인] 날짜가 되면 자동으로 기록이 남는다.
- [가정] 방법: 앱을 열 때 마지막으로 처리한 날부터 오늘까지 빠진 고정 항목을 한꺼번에 만든다 (서버 상시 실행 없이 0원 유지).
- [가정] 같은 고정 항목·같은 회차는 두 번 만들지 않는다.
- [확인] 고정 항목의 금액·날짜는 수정할 수 있다.
- [가정] 수정은 다음 회차부터 적용하고, 이미 만들어진 지난 기록은 바꾸지 않는다.
- [확인] 카드값 중복 문제는 별도 기능으로 막지 않는다 (사용자 판단).

### 5-5. 예산 (②)
- [확인] 예산 관리를 넣는다.
- [가정] 1차는 '한 달 총예산' 하나만: 사용 금액 · 남은 금액 · 남은 날 기준 하루 쓸 수 있는 금액.
- [가정] 예산 기간은 매달 1일~말일. 저축/투자 분류와 '금액 입력 필요' 상태는 계산에서 뺀다.
- [가정] 분류별 예산, 80% 도달 알림은 v2.

### 5-6. CSV 내보내기 (②)
- [확인] 데이터 내보내기는 CSV 파일로 한다.
- [가정] 엑셀에서 열어도 한글이 깨지지 않게 만든다.
- [가정] 열: 날짜, 종류(지출/수입), 금액, 가게, 분류, 결제수단, 메모.
- [보류] CSV 가져오기는 필요해지면 추가.

### 5-7. 이미지 읽기 (③)
- [확인] 종이 영수증, 전자영수증, 카드·은행 앱 내역 캡처를 모두 받는다.
- [확인] 날짜·금액·가게 이름을 읽어 채운다. 카드번호·카드사는 읽지 않는다.
- [확인] 읽은 값은 모두 수정할 수 있다.
- [가정] 읽은 결과를 한 번 보여주고 '저장'을 눌러야 등록된다. 여러 건이면 목록으로 보여주고 빼거나 고칠 수 있다(취소 건 등).
- [가정] 영수증에서 읽힌 품목은 메모에 붙여두기만 한다.
- [확인] 가게 이름을 고치면 그 짝을 기억해 다음부터 고친 이름으로 미리 채운다 (글자가 똑같을 때만).
- [가정] 같은 날짜·금액·가게가 이미 있으면 "이미 있어요"라고 알려준다.
- [가정] 이미지 원본은 읽고 나면 지운다.
- [미확인] 읽는 방식 (운영비 0원 안에서). ① 단계 동안 실제 영수증으로 미리 시험.

### 5-8. 알림 (④)
- [확인] 정리하라고 불러주는 알림을 넣는다.
- [가정] 주 1회, 요일·시간은 사용자가 정한다 (예: 일요일 밤 9시).
- [가정] '금액 입력 필요' 고정 지출이 있으면 알림에 함께 알려준다. 예: "이번 주 정리할까요? 금액 입력이 필요한 고정 지출 2건이 있어요"
- [미확인] 웹앱에서 0원으로 알림을 보낼 수 있는지 (특히 아이폰). 안 되면 다른 방법을 찾는다.

## 6. 데이터 구조 (초안)

> 모든 테이블에 `user_id`(로그인 사용자)가 있고, 본인 데이터만 접근 가능하다. [가정]
> 금액은 원 단위 정수. 날짜는 날짜형(시간 없음).

### ① 최소 버전

**payment_methods — 결제수단**
| 컬럼 | 설명 |
|---|---|
| id | |
| user_id | |
| type | `cash`(현금) / `card`(카드) / `transfer`(계좌이체) |
| name | 별칭 (예: 신한 체크, 토스 통장) |
| sort_order | 목록 순서 |
| is_active | 숨김 처리용 (지우면 지난 기록이 깨지므로 숨김으로 처리) [가정] |

- [가정] 가입하면 '현금' 하나를 자동으로 만든다.

**categories — 분류**
| 컬럼 | 설명 |
|---|---|
| id | |
| user_id | |
| name | 분류 이름 |
| kind | `expense`(지출용) / `income`(수입용) |
| is_savings | 저축/투자 분류 표시 (통계·예산에서 따로 계산) |
| is_refund | 환불 분류 표시 (수입 합계에서 빼고, 지출 합계에서 차감) |
